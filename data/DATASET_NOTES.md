## Correlation Logic

The dataset was generated with **realistic correlations, not pure randomness**. The following rules govern `ground_truth_recoverable` and `ground_truth_best_action`, with a noise layer applied to each record:

| Failure Code | Primary Rule | Noise / Exceptions |
|---|---|---|
| BANK_TIMEOUT | recoverable=TRUE, action=RETRY_NOW (RETRY_LATER if retry_count≥2) | 15% chance: recoverable=FALSE, action=RETRY_LATER |
| ISSUER_UNAVAILABLE | same as BANK_TIMEOUT | same 15% noise |
| OTP_TIMEOUT | same as BANK_TIMEOUT | same 15% noise |
| CARD_EXPIRED | recoverable=TRUE, action=SEND_UPDATE_LINK | 10% chance: recoverable=FALSE, action=STOP |
| CARD_DECLINED_HARD (failures≥3) | recoverable=FALSE, action=STOP | 15% chance: ESCALATE_HUMAN if LTV>₹15,000 |
| CARD_DECLINED_HARD (failures<3) | recoverable=TRUE, action=RETRY_LATER | 20% chance: recoverable=FALSE, action=STOP |
| CARD_DECLINED_SOFT (failures≥3) | recoverable=FALSE, action=STOP | 25% chance: ESCALATE_HUMAN if LTV>₹20,000 |
| CARD_DECLINED_SOFT (failures<3) | recoverable=TRUE, action=RETRY_LATER | 15% chance: recoverable=FALSE, action=STOP |
| INSUFFICIENT_FUNDS (failures≥4) | recoverable=FALSE, action=STOP | 20% chance: ESCALATE_HUMAN if LTV>₹10,000 |
| INSUFFICIENT_FUNDS (failures<4) | recoverable=TRUE, action=RETRY_LATER | 15% chance: recoverable=FALSE, action=STOP |
| RISK_FLAGGED | action=ESCALATE_HUMAN (always); recoverable=random ~55% | No additional noise |

**High-LTV override:** For cases with high customer_ltv, the generator may override STOP with ESCALATE_HUMAN to simulate "worth a human look for customer value" — applied within the noise percentages above.

## Planted Edge Cases (held_out_test_set.csv only)

These 5 records have `is_planted_edge_case = TRUE`. They contain deliberately conflicting signals designed to trigger low-confidence escalation in Phase 6. They are **not mislabeled** — they have valid ground truth, but a rules-based or pattern-matching system would struggle to classify them correctly without reasoning about the conflict.

| Payment ID | Conflict Description |
|---|---|
| PMT-00121 | **BANK_TIMEOUT (TEMPORARY) + retry_count=3 + previous_failures=5.** The failure code signals "just retry" but the retry budget is fully exhausted and the failure history is high. Rule says RETRY_NOW; context says the retries haven't worked. Ground truth: ESCALATE_HUMAN. |
| PMT-00122 | **CARD_EXPIRED + customer_ltv=₹5,12,500 + 41 prior successes.** The rule clearly maps CARD_EXPIRED → SEND_UPDATE_LINK. But this is the merchant's highest-value, longest-tenured customer — economics argue for a human white-glove call instead of an automated link. Ground truth: ESCALATE_HUMAN. |
| PMT-00123 | **CARD_DECLINED_HARD (PERMANENT) + previous_failures=0 + 18 prior successes.** The failure code is categorically permanent, but this customer has an 18-payment clean record and zero prior failures — suggesting this could be a bank-side error or wrong card on file. Ground truth: SEND_UPDATE_LINK (try new card details before giving up). |
| PMT-00124 | **INSUFFICIENT_FUNDS (AMBIGUOUS) + previous_successes=36 + previous_failures=4.** The customer has a 36-payment loyalty track record (highly unusual to just stop paying) but also 4 recent failures. Could be payday timing, could be genuine financial distress. Ground truth: RETRY_LATER (loyalty wins). |
| PMT-00125 | **RISK_FLAGGED + customer_ltv=₹149 + subscription_age_days=35.** The RISK_FLAGGED rule mandates ESCALATE_HUMAN regardless of context. But the customer is brand new (35 days), has minimal LTV (₹149), and 2 prior failures — human review costs more than the potential recovery. Ground truth: STOP. |
